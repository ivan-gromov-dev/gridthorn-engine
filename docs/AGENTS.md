# Documentation Instructions

- Distinguish planned, provisional, implemented, and stable behavior explicitly.
- Keep roadmap checkboxes evidence-based; an item is complete only when its
  behavior, tests, diagnostics, and documentation exist.
- Use terminology from `GLOSSARY.md` consistently.
- Keep exact dependency versions in Cargo manifests and `Cargo.lock`, not in
  technology prose, except for compatibility contracts such as the MSRV.
- Add an ADR before stabilizing a difficult-to-reverse architecture decision.
- Update links and status tables when moving or renaming documented artifacts.
